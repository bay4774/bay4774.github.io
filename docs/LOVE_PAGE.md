# 恋爱纪念页维护

主页的“恋爱纪念”入口打开 `/love/`。页面先要求密码，解锁后显示相识计时、故事、照片与信件，可按需播放原目录中的歌曲。当前页面只供查看，不包含原旧站中缺少服务端实现的日记保存功能。

## 文件与隐私边界

- `.private/love/content.json`：故事、姓名、日期、图片说明和素材来源路径，只在本地保存。
- `.private/love/password.txt`：一行访问密码，只在本地保存；也可用 `LOVE_PASSWORD` 环境变量覆盖。
- `../Love/`：原照片和音乐，打包时只读取，不修改。
- `public/love/vault.json`：故事与压缩照片的密文。
- `public/love/song.json`：音乐的独立密文，点击播放时才下载和解密。

`.private/` 已在 `.gitignore` 中，不能将上述私有文件复制到 `src/content/`、`public/` 或其他可发布目录。照片在内存中转为 WebP，长边最多 1400 像素，自动校正方向并去掉 EXIF 元数据；公开目录只写加密结果。加密后的内容不带原素材路径。

公开页面和脚本不含访问密码、姓名、相识日期或照片明文。解锁依赖浏览器 Web Crypto，正式访问需 HTTPS，本机预览可用 `http://localhost` 或 `http://127.0.0.1`。禁用 JavaScript 时无法解锁。

## 更新内容或更换密码

1. 编辑 `.private/love/content.json`，保留 `version: 1`。`meetDate` 必须包含时区；此日期表示“相识”，不要误标成确定恋爱关系的日期。图片和音乐的 `source` 都是相对于 `Love` 目录的路径。
2. 在本机编辑 `.private/love/password.txt`，写入一行非空密码。不要把密码加入脚本、命令参数或提交记录。
3. 在项目根目录运行：

   ```text
   node scripts/prepare-love.mjs --source-dir ../Love
   pnpm build
   pnpm test
   ```

4. 检查解锁、图片和音乐后，将两个加密 JSON 与代码一起发布。两份密文需来自同一次打包，尤其在改密码时。

打包工具也可读取已经设置好的 `LOVE_PASSWORD` 环境变量；变量存在时优先使用它，空值会报错。不要在截图、日志或共享终端中显示该变量。打包工具不打印密码与私有文案。

普通 `pnpm build` 只复制已经生成的密文，不读取 `.private/`，也不依赖上级 `Love` 目录。因此把代码与密文同步到其他电脑或 CI 后仍能正常构建。只有重新整理照片、改内容或更换密码时才需要本地原素材、私有内容和密码。

## 加密说明

使用 PBKDF2-SHA-256（600,000 次迭代）从密码派生 AES-GCM-256 密钥，每次打包使用随机盐与随机 IV，验证标签可检测密码错误或密文被改动。密码不以明文或可直接比较的值发布，照片和音乐不会通过普通静态资源路径公开。

静态密文可以被任何访客下载，并在离线环境中尝试猜测密码。较长、独特的密码更能抵抗这种尝试；六位数字密码的可能组合有限。浏览器内的重试提示不能阻止离线猜测。

更换密码后需要重新打包并发布两份密文。它不会撤回别人已经下载的旧密文、旧密码、截图或解密副本。这里提供的是静态加密查看页，没有服务端账户、远程会话撤销或强制限流。
