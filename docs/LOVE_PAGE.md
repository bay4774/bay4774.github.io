# 恋爱纪念页维护

主页的“恋爱纪念”入口打开 `/love/`。页面先要求密码，解锁后显示相识与在一起的纪念信息、合照、旅行和日常照片、两封信与原站承诺，可按需播放歌曲并阅读歌词。云端连接启用后，可以直接上传照片、撰写或编辑恋爱日记，以及添加一次性或每年重复的纪念日。

## 文件与隐私边界

- `.private/love/content.json`：故事、姓名、日期、图片说明和素材来源路径，只在本地保存。
- `.private/love/password.txt`：一行访问密码，只在本地保存；也可用 `LOVE_PASSWORD` 环境变量覆盖。
- `.private/love/imports/`：用户后来提供的原始照片，只在本地保存。
- `../Love/`：原照片和音乐，打包时只读取，不修改。
- `public/love/vault.json`：故事与压缩照片的密文。
- `public/love/song.json`：音乐的独立密文，点击播放时才下载和解密。
- `backend/love-storage/`：云端存储服务的代码与测试；实际由独立 Sites 项目部署，动态记录保存在其 R2 存储桶。

`.private/` 已在 `.gitignore` 中，不能将上述私有文件复制到 `src/content/`、`public/` 或其他可发布目录。照片在内存中转为 WebP，长边最多 1400 像素，自动校正方向并去掉 EXIF 元数据；公开目录只写加密结果。加密后的内容不带原素材路径。

公开页面和脚本不含访问密码、私人姓名、纪念日期、信件、歌词、照片明文或云端访问令牌。解锁依赖浏览器 Web Crypto，正式访问需 HTTPS，本机预览可用 `http://localhost` 或 `http://127.0.0.1`。禁用 JavaScript 时无法解锁。

## 在网页中持续更新

- 在“回忆相册”中选择照片，填写标题、说明和分类后保存；“我们的合照”“旅行记忆”“日常里的你”分别筛选相应照片。
- 在“恋爱日记”中填写日期、标题、正文和署名，保存后可重新打开该篇日记编辑。
- 在“纪念日”中填写名称、日期和说明，选择仅此一次或每年重复。新增日期会显示在月历和即将到来的纪念日列表中。

以页面明确显示的保存成功状态为准。网络错误时保存结果可能尚未确认；不要把仍在表单里的内容当作已同步，保留表单并重试即可，重试会复用同一记录标识避免重复添加。两个设备可以在解锁后读取同一个云端纪念册，日记更新使用版本校验，避免较旧的编辑覆盖另一台设备刚保存的版本。

网页新增内容属于云端增量记录，不回写 Git 仓库或 `public/love/vault.json`。重新部署静态主页不会清空这些记录，重新打包基础纪念册也不会自动把云端新增内容并入基础密文。目前不提供删除记录或在线修改访问密码的功能。

## 云端存储与访问

GitHub Pages 继续托管原有主页、查看界面和基础密文。Sites 的 Cloudflare Worker API 接收浏览器加密后的增量记录，R2 保存照片、日记和自定义纪念日的独立密文。服务端不接收纪念册密码，也不解密正文或照片；记录编号、类型、创建时间和版本标识作为服务元数据保存。

当前服务来源地址为 `https://love-journal-storage-bay4774.largemask4.chatgpt.site`。地址本身可以公开；真正的访问令牌只能放在本机私有内容和加密后的基础纪念册中。

`cloud.token` 是与访问密码独立生成的随机令牌。浏览器输入密码、解开基础纪念册后才获得它，再通过 HTTPS 的 `Authorization` 请求头访问云端。Worker 的 `LOVE_TOKEN_SHA256` 运行时密钥只保存该令牌的 SHA-256 摘要，并在每次 API 读取或写入时核验。不要把真实令牌、摘要配置或密码写进源码、日志、截图或部署脚本参数。

本服务已取得用户对开放 API 网络连接的明确确认，Sites 访问范围设为 public，供现有 GitHub Pages 页面跨域调用。所有 `/api/*` 数据请求仍需令牌验证；CORS 只允许配置的主页来源及明确添加的本机预览来源，预检请求不读取或写入记录。以后新建其他 Sites 默认仍是仅所有者可访问，不能因部署需要自行改变访问范围。各端点、R2 绑定及运行时配置见 `backend/love-storage/README.md`。

## 维护基础纪念册

1. 编辑 `.private/love/content.json`，保留 `version: 1`。`meetDate` 必须包含时区，表示“相识”；`relationshipDate` 使用 `YYYY-MM-DD`，表示正式在一起，二者分别维护。普通图片和音乐的 `source` 相对于原素材 `Love` 目录；以 `imports/` 开头的照片路径仅映射到本机 `.private/love/imports/`，不修改原素材目录。
2. 在本机编辑 `.private/love/password.txt`，写入一行非空密码。不要把密码加入脚本、命令参数或提交记录。
3. 在项目根目录运行：

   ```text
   node scripts/prepare-love.mjs --source-dir ../Love
   pnpm build
   pnpm test
   ```

4. 检查解锁、图片、音乐和云端连接后，将两个加密 JSON 与代码一起发布。两份密文需来自同一次打包。若云端已经保存记录，不要只替换密码并重打基础包；先按下方说明规划历史记录迁移。

打包工具也可读取已经设置好的 `LOVE_PASSWORD` 环境变量；变量存在时优先使用它，空值会报错。不要在截图、日志或共享终端中显示该变量。打包工具不打印密码与私有文案。

普通 `pnpm build` 只复制已经生成的密文，不读取 `.private/`，也不依赖上级 `Love` 目录。因此把代码与密文同步到其他电脑或 CI 后仍能正常构建。只有重新整理照片、改内容或更换密码时才需要本地原素材、私有内容和密码。

## 内容字段与来源

加密载荷继续使用 `version: 1`，新增字段均可省略，旧内容仍可打包。脚本按白名单挑选字段，不会把额外私有备注、密码或素材来源路径带进公开载荷。

| 字段 | 维护规则 |
| --- | --- |
| `meetDate` | 含时区的相识时间；必须是真实有效日期。 |
| `relationshipDate` | 已确认的正式在一起日期，格式 `YYYY-MM-DD`，不能早于相识。 |
| `heroPhotoIndex` | 封面照片在 `photos` 数组中的索引，从 0 开始；必须指向已有照片。 |
| `storyPhotoIndexes` | 为每个故事章节指定照片索引；数组长度须与 `chapters` 相同，各索引必须指向已有照片。 |
| `photos[].category` | `couple`、`travel` 或 `daily`，分别用于合照、旅行与日常筛选；基础纪念册当前含 1 张合照、12 张旅行照片和 12 张日常照片。 |
| `photos[].source` | 普通路径相对于原 `Love` 根目录；`imports/文件名` 相对于 `.private/love/imports/`。两个来源均拒绝目录越界和符号链接越界。 |
| `music.lyrics` | 原 `LYX/confession.html` 中的歌词行数组；空字符串保留段落间隔。未提供歌词时省略，不补写或推断版权信息。 |
| `loveNotes` | `{title,text}` 数组；当前内容来自原告白页的认真、偏爱、陪伴三个承诺。 |
| `letters` | `{id,title,context,date?,paragraphs,signature}` 数组；`id` 必须唯一，日期如有则用真实日历日期。 |
| `letter` | 原单封告白信，继续保留供旧版页面兼容。 |
| `cloud` | `{apiUrl,token}`；地址必须是无路径、参数或凭据的 HTTPS 来源，令牌必须是 64 位小写十六进制随机值，仅进入加密载荷。 |

第一封信沿用旧站告白原文，标注“在一起之前”，因为原文未提供写作日期而不填日期。第二封纪念信根据已确认的关系状态撰写，日期使用 `relationshipDate`，未添加未经提供的具体经历。后续调整文案时应保留这一区别，不把新写的纪念文字当作旧站原文。

初始内容没有推断生日；后续可由两人在网页中主动添加生日等自定义纪念日。用户后来提供的合照保存在私有导入目录，并同时用于故事时间线第一张图片和“我们的合照”分类；没有把图片水印自动当作纪念日。

在单独工作树中运行打包时，`../Love` 可能不是原素材所在位置；将 `--source-dir` 改成原素材目录的实际绝对路径。脚本会拒绝目录越界、符号链接越界、无效日期、未知照片类别和失效的封面索引。可单独执行 `node --test tests/love-content.test.mjs` 验证内容规则。

## 加密说明

使用 PBKDF2-SHA-256（600,000 次迭代）从密码派生 AES-GCM-256 密钥，每次打包使用随机盐与随机 IV，验证标签可检测密码错误或密文被改动。密码不以明文或可直接比较的值发布，照片和音乐不会通过普通静态资源路径公开。

静态密文可以被任何访客下载，并在离线环境中尝试猜测密码。较长、独特的密码更能抵抗这种尝试；六位数字密码的可能组合有限。浏览器内的重试提示不能阻止离线猜测。

密码既用于解密基础包，也用于解密云端历史记录。目前没有在线改密码功能：维护者若要更改密码，必须先使用旧密码逐项解密云端记录，再使用新密码重新加密并有版本校验地写回，同时重打基础故事与音乐密文。仅修改 `.private/love/password.txt` 并发布新基础包，会使旧云端内容无法用新密码读取。迁移工具和恢复流程尚未提供，不应把静态重打包当成完整换密操作。

轮换云端令牌与修改内容密码是不同操作。令牌轮换需同步更新 Worker 的 `LOVE_TOKEN_SHA256` 与加密基础包中的 `cloud.token`，旧令牌随后不能调用 API；它不会撤回别人已经下载的旧密文、旧密码、截图或解密副本。服务采用共享纪念册权限，没有每人独立账户或在线密码恢复。
